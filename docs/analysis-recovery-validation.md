# 全书分析中断恢复修复

## 现场与修复范围

2026-09-07 只读核对日常数据库：45 个分节、17 个章节汇总及两份中间全书摘要均已保存，最终全书概要为空，状态为 error。旧版本仅留下通用错误，因此无法还原失败响应的实际长度；超出 1,600 字符是与代码和阶段相符的可能原因，不能当作已捕获的服务端事实。

本次修复保留分析内容格式、缓存指纹和已有会话 ID，不提高摘要验收上限，也不截掉模型输出后冒充完整摘要。新版本继续复用有效分节、章节和中间汇总；初始提示与缓存节点划分保持一致。

- 汇总为空或过长时，带着具体长度及更简洁的要求，从同一组输入重新生成；分节笔记继续校验结构与原文编号。
- 每个步骤共享最多 3 次尝试的预算，临时接口错误也使用此预算。重试等待 1 秒、2 秒，可取消，并在下一次请求前让出给阅读问答；密钥、配置及 Go 会话拒绝等不可重试错误直接停止。
- 分析请求总时限由 90 秒调整为 180 秒，阅读问答和取材规划的时限不变。时限仍为单次请求总时长，持续输出不会无限延长。
- 显示分节分析、章节汇总及全书合并进度，全书合并显示当前轮次；失败提示位于控制区顶部，最近失败记录可展开查看。
- 迁移 11 新增进度与最近 10 条失败记录，只保存阶段、错误码、安全提示、时间、尝试次数及可用的字符数。正文、失败响应及凭据不写入记录；续跑和重启保留记录，重建或删除书籍时清除对应记录。
- 界面说明有限重试可能消耗额度。退出或重新打开程序不会自动续跑。

## 验证方法

全部自动验证使用内存数据库、隔离测试目录及本机 HTTP 模拟接口，不调用用户模型。

- `tests/unit/backend-book-analysis.test.ts`：复现 45 分节、17 章节、两份中间摘要均已缓存的场景；检查 Unicode 字符计数、过长修复、连续失败次数上限、空白结果、超时/限流重试、凭据错误立即停止、取消重试、会话 ID 稳定，以及只补最后一次合并。
- `tests/unit/backend-provider-transport.test.ts`：从迁移 10 升级及重复打开，验证指纹、时间戳、会话 ID 和已有摘要保持不变；失败历史跨重启保存、最多 10 条，重建清理。
- `tests/e2e/analysis-recovery.spec.ts`：真实 Electron 中检查自动重试、明确错误、阶段进度、重启后保留记录、缓存续跑、恢复全书输入框；覆盖明暗主题、1440×900 与 940×600，截图位于 `test-results/analysis-recovery-*/`。
