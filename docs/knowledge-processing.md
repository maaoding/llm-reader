# 知识处理设置与接口说明

全书上下文支持可选的语义检索、证据重排以及 PDF 文档处理。功能默认关闭；不自动下载模型、安装服务或调用付费接口。

## 设置与使用

1. 打开 **设置 → 知识处理**。问答和章节分析仍使用原“模型”设置。
2. 需要语义检索时，勾选“启用语义检索”，填写 Embedding 地址（例如 `http://localhost:11434/v1`）、已部署的模型名及必要的 API Key。兼容 `/v1/embeddings`，输入字符串数组，返回浮点向量。此处需要 Embedding 模型，不是聊天模型；本机无鉴权服务可留空密钥。
3. “测试 Embedding”使用当前表单发送一条固定短文本，可能消耗少量额度。保存后，在原文已准备的书籍中展开“语义索引”，点击“建立语义索引”，无需先生成章节笔记。标题路径与正文分批发送到该接口；向量存入本机 SQLite，无需独立向量数据库。
4. 索引就绪后，本书问答融合关键词与语义检索。每个问题及所选段落可能发送到 Embedding 接口；该接口失败时继续使用关键词检索。历史回答、向量和摘要都不作为原文依据。
5. 需要 PDF 原文检索时，选择文档服务、服务根地址、OCR 和语言。“检查处理服务”不会上传书籍；本地服务检查异步 API 是否存在，实际处理能力及鉴权仍需书籍任务验证。保存后在“原文与章节笔记”中点击“准备原文”，只将整份 PDF 发送至文档服务。原文就绪即可问答；需要笔记时再单独选择模型并“生成章节笔记”，这一步才把分节原文发送至分析模型。

可配置 HTTPS 服务，或本机 `localhost`、`127.0.0.1`、`[::1]` 的 HTTP 服务。地址不能包含用户名、密码、查询参数或片段；不跟随重定向。更换地址或处理服务时，原密钥不会被转发到新接口，请重新填写。

## 证据重排

在 **设置 → 知识处理 → 证据重排** 填写独立的服务地址、重排模型和 API Key。可与 Embedding 使用不同厂商；已有 Embedding 密钥不会自动复制到重排。首个兼容目标是硅基流动文本接口，例如地址 `https://api.siliconflow.cn/v1`、模型 `BAAI/bge-reranker-v2-m3`，模型当前是否可用以所选服务为准。

“测试重排”使用当前未保存表单，发送雨天带伞的固定问题和两条短文本，不上传书籍；测试成功不代表配置已保存。勾选“启用证据重排”并保存后，后续适用的问答自动使用它，无需每轮打开。清除密钥、修改模型和启用状态均计入未保存修改。更换地址后需要重新填写密钥；停用会保留已保存密钥，勾选“清除密钥”再保存才删除。

问答时问题、最多 600 字选区、已有规划词，以及最多 60 条带章节标题的完整原文会发送到所选服务。仅在原文已准备、进入书内检索且候选至少两条时调用，无需先生成章节笔记；不需要重建章节笔记或已有向量。语义索引尚未准备好时仍可重排全文检索结果；原文尚未准备时的局部解释沿用原有流程。

每轮只请求一次，额外等待最多 5 秒。网络、鉴权、限流、格式等错误会继续使用本轮融合检索结果，在回答的原文来源折叠区显示“重排未完成，已使用原检索结果”；成功时显示“证据已重排”。取消问答或删除书籍会终止整个请求。重排不改变章节分析、语义索引或 PDF 处理任务的状态。

本地先保护选区、最多两条邻近原文和最多六个目标章节的原文代表，再填入其余排序原文，补充原文总计最多 12 条。关联脚注或同单元邻接原文只使用剩余名额，并排除已有命中；不会挤掉已经入选的直接证据。预算不足时可截短代表原文；来源区和引用只使用本次实际发送的文字。缩减重试复用排序，重新生成本轮引用编号。全书概要和章节笔记仍是背景，不作为原文证据。

协议使用 `POST <baseUrl>/rerank`，请求 `model`、`query`、字符串数组 `documents`、覆盖全部候选的 `top_n`、`return_documents: false`。只读取 `results[].index` 与有限的 `relevance_score`；部分有效结果后追加未返回的候选，分数相同保持原顺序。空、重复或越界结果会整体回退；供应商返回的正文和引用编号不进入上下文。响应最多 1 MiB，不自动重试或跳转，不支持自定义请求头及多模态候选。

升级迁移保留旧设置 JSON、加密密钥和 revision；默认重排关闭且地址、模型为空。旧版保存输入没有 `rerank` 时保持现有重排配置。新归档记录本轮重排状态、模型、候选数量、耗时及受控原因，旧归档无需迁移也能读取、追问、导出。实现与对照边界见[重排验收记录](rerank-validation.md)。

接口依据：2026-09-08 核对[硅基流动重排 API](https://docs.siliconflow.cn/docs/api/rerank-post)。

## 文档服务协议

| 服务 | 地址示例 | 使用的协议 | 鉴权 |
| --- | --- | --- | --- |
| Docling Serve | `http://localhost:5001` | `POST /v1/convert/file/async`，`GET /v1/status/poll/{id}`，`GET /v1/result/{id}` | 可选 `X-Api-Key` |
| MinerU 本地 | `http://localhost:8000` | `POST /tasks`，`GET /tasks/{id}`，`GET /tasks/{id}/result` | 可选 Bearer（用于自行配置的反向代理） |
| MinerU 云端 | `https://mineru.net` | `/api/v4/file-urls/batch` 申请上传，预签名 PUT，`/api/v4/extract-results/batch/{id}` 查询，下载结果 ZIP | API 请求使用 Bearer；预签名上传和结果下载不带 Token |

MinerU 使用 **pipeline** 后端及 `content_list.json`，启用文字、表格与公式识别，OCR 选择映射到 `ocr/txt` 或云端 `is_ocr`。本地服务须支持异步 `/tasks`；不对只提供旧版 `/file_parse` 的服务进行无提示降级。

Docling 请求 JSON 输出、占位图片，并使用 EasyOCR 的中文/英文语言码；服务需具备相应引擎。通过 `ocr_preset=easyocr` 指定新版引擎，同时保留旧版 `ocr_engine` 字段。应用保留正文树、阅读顺序、有效来源页/坐标、表格单元格及真实表头、跨度和明确脚注/表注关联，再派生处理批次。只接受 `success`，`partial_success` 不标记全文就绪。

文档最多 200 MB、600 页。返回的图片、脚本、HTML、外部链接不执行或加载；MinerU HTML 表格仅由 `parse5` 读取语法树与文字。原始解析产物最多缓存 48 MB，规范化结构最多 96 MB。OCR 结果用于检索和可选笔记，不改变扫描页划词能力；多页来源可逐页跳转，没有行级来源时明确显示整表范围。文档检查仅提示可能的问题，不代表 OCR 准确率。

## 暂停、重建与兼容

- 建立语义索引每批最多 16 段，完成一批就保存；暂停、关闭、重启后均需用户主动续跑。单书向量上限 128 MiB，维度最多 4096。更换 Embedding 地址、模型或密钥后重建索引；章节笔记和归档保留。只关闭/再打开语义检索可继续使用原索引。
- PDF 任务保存远端任务编号、原始产物及已校验结构。暂停只停止本机等待，远端可能继续运行；继续准备优先读取同一任务。MinerU 云端的 `waiting-file` 也可能表示上传后等待入队，应用继续等待。每轮等待最多 30 分钟，超时后可继续查询；单次 HTTP 默认 60 秒，云端文件传输最多 3 分钟。
- 上传过程中断、提交结果不确定、任务失败或远端任务已过期时，需要点击“重新准备原文”。应用不会自动创建第二个付费任务。重新准备优先复用同一配置下可用的原始产物，否则可能重新上传；相关笔记与向量待重建，已有归档快照保留。“重新生成章节笔记”只重建笔记，“重建语义索引”只重建向量。
- 删除书籍取消本机任务，并清理分析、原文索引、向量和处理结果；不自动删除第三方服务保存的文件或任务。第三方保存期限由其配置和政策决定。
- 数据库迁移不改旧配置更新时间、分析指纹、会话 UUID、笔记或归档。新增密钥使用系统 safeStorage 加密后写入 SQLite，主进程负责解密和请求。
- 自动回归使用固定数据和本地模拟服务。2026-09-07 另经用户授权，以自建短样本完成硅基流动 `BAAI/bge-m3` 与 OpenCode Go 的[真实接口验收](knowledge-live-validation.md)。2026-09-08 完成 [MinerU 云端扫描 PDF 验收](mineru-live-validation.md)，覆盖中文、表格、全书问答和页码引用，未上传个人书籍。Docling、MinerU 本地服务和复杂文档 OCR 准确率仍未实测；不同服务的限额和连通性以实际配置为准。
