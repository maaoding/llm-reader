## 方法

- 使用前一轮固定的长篇 EPUB、数字 PDF 和纯图扫描 PDF，样本及题目 SHA-256 均与[原记录](independent-reading-validation.md)一致。
- 三份资料均经生产导入和原文准备。EPUB 使用真实本地提取；本机 Docling 服务分别核对两份实际上传 PDF 的 SHA-256，再从冻结 `pdfPages` 构造包含表格、脚注和页码的结构。这部分是模拟解析，未进行实际 PDF 解析或 OCR。
- 规划使用首次调用前已固定的通用中英关键词映射，不读取标准答案。规划函数 SHA-256 为 `50126b9460194edaa23db1a10b7bd8e7f0ad3723084603ab9903f26b27e13ede`，正式运行后没有调整。
- 每题均走生产 `startLlm` 请求和检索路径；两道跨书题创建独立工作台，取材仅限本轮指定书籍。一个不继承评测历史的读者代理只读取该题队列中的实际 `question/reference/messages`，独立写出回答，没有读取材料源码、预期证据或标准答案。服务再以 OpenAI 兼容 SSE 返回该回答。
- 根会话逐题对照回答、实际引用原文和固定预期复核。回答方与复核方分开；没有根据预期证据向回答方补充漏检原文。

## 执行与证据

```bash
node scripts/independent-reading-generate.mjs
pnpm eval:independent-reading --simulate \
  --report-dir output/independent-reading-simulation-20261020
```

无桌面的 Linux 使用 Xvfb 启动。模拟运行仅在一次性配置目录中保存合成凭据，可使用 `LLM_READER_E2E_BASIC_TEXT=1` 允许该隔离测试目录的 Electron `basic_text` 后端；真实配置运行不得因此改变加密后端。

脚本依次生成 `queue/request-001.json` 至 `request-012.json`，等待同目录的 `answer-001.json` 等文件，格式为 `{"answer":"只依据本轮原文作答并使用实际引用编号。"}`。应使用临时文件加 rename 写入；读者不得读取报告中的期望证据。`--simulate`、`--offline`、`--run` 互斥。

本机证据在 `output/independent-reading-simulation-20261020/`：

- `report.json`、`report.md`：逐题请求、实际上下文、完整回答、来源和人工复核。
- `report.unreviewed.json`、`report.unreviewed.md`：复核前的生成记录。
- `simulation-trace.json`：固定规划、两份 PDF 实际上传摘要及逐题回答摘要。
- `queue/`：回答方实际看到的请求，以及其原子写入的12份回答。
- `review.json`：复核汇总。

启动阶段曾因模拟脚本把只读 `hasApiKey` 状态传给严格的配置保存接口而被拒绝，当时尚未准备材料或进入题目。修正为显式保存参数后运行成功；失败及诊断记录分别保留在 `output/independent-reading-simulation-startup-failed-20261020/` 和 `output/independent-reading-simulation-config-failed-20261020/`，没有放宽产品参数校验。

验证通过：`pnpm lint`、`pnpm typecheck`、58个文件／495项单元测试。新增的本机服务测试验证独立上传任务、未知 PDF 拒绝、实际上下文队列与流式回包；文档结构测试覆盖表格、脚注、页码和阅读顺序。

这些结果是软件联调与受控阅读模拟。耗时包含助手等待，没有真实供应商 token、费用或时延数据；未逐一操作桌面上的每个引用跳转，也未验证真实 OCR 或真实模型质量，不能据此推断真实书籍上的普遍准确率。
