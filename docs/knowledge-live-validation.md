## Go 请求与回退

通过 Electron 主进程的 Node `diagnostics_channel` 观测实际发出的请求，只提取公开域名、路径、方法、HTTP 状态、真实客户端标识，以及匿名化后的会话分组；不记录 Authorization 或密钥。

- 捕获 11 个 Go 请求和 4 个应用内 Embedding 请求，均收到 HTTP 200 响应头。独立的硅基流动模型列表及三文本向量探测不在这 15 个应用请求中。
- Go 请求携带 `User-Agent: LLM-Reader/0.4.0` 和合法 UUID `x-opencode-session`。
- 5 个章节分析/汇总请求复用同一分析会话；两轮问答及其规划共 4 个请求复用另一会话；连接探测采用独立会话。硅基流动请求没有附带 Go 会话头。
- 第二轮规划在收到 HTTP 200 后未能于 12 秒预算内完成，应用取消该流并使用本地检索回退，后续回答完成。因此结果是“业务流程通过，出现一次规划超时回退”，不是所有请求正文均无异常。

该超时不需要通过增加请求头或更换 Key 解决。当前回退符合一期设计；此次检查未修改应用超时、模型参数或日常配置。
