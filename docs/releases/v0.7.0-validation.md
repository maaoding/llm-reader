## 验证

环境：Debian 13 x64、Node `24.19.0`、pnpm `11.22.0`、Electron `43.3.0`。按锁文件恢复依赖，使用 Xvfb 运行实际 Electron 应用；模型、联网搜索和文档服务均使用本机模拟接口与合成凭据。Linux 无系统密钥环，测试通过已有 `LLM_READER_E2E_BASIC_TEXT=1` 开关，仅对每个用例的临时书库启用测试用凭据存储；没有修改应用安全配置。

| 检查 | 本次结果 |
| --- | --- |
| lint、typecheck | 通过 |
| 单元测试 | 53 个文件、458 项通过 |
| Electron 应用构建 | 通过 |
| 完整 Electron E2E | 109 项中 104 通过、3 失败、2 跳过；`pnpm test:all` 退出码为 1，不能记为全量通过 |

| 官网本地检查 | Chromium 1440px / 390px 布局无横向溢出，版本为 v0.7.0；演示提问与引用返回交互通过，无页面脚本错误 |
| 差异检查 | `git diff --check` 通过 |

三项失败均停在 Windows 专属能力的断言：

- `reading-font.spec.ts`：主进程调用 `powershell.exe` 枚举字体，Linux 环境没有该程序，字体列表为空。
- `select-style.spec.ts`：同样在等待字体列表的 `optgroup` 时失败，尚未进入该用例后面的下拉菜单检查。
- `window-chrome.spec.ts`：Linux Electron 的 `nativeImage` 未能加载 Windows ICO，窗口最大化与还原检查尚未执行。

两项跳过分别需要本机 Calibre 和 `LLM_READER_REAL_PDF` 指定的个人复杂 PDF，本环境均未提供。没有为取得通过结果而修改、放宽或新增跳过条件。

通过的桌面用例包含助手设定浮层、长问题输入、两种对话页面、联网搜索与来源打开校验、会话恢复、PDF 缩放和 EPUB 内容安全策略回归。已目视检查浅色助手设定、深色窄窗口输入区与对话来源区；官网宽窄窗口截图也已检查。原始日志和官网截图保存在忽略目录 `output/release-v0.7.0/`，桌面截图、失败上下文与 trace 在 `test-results/`。

## Windows 构建

已生成版本为 0.7.0 的 `release/win-unpacked` 应用目录和 NSIS 安装包。应用为 Windows x64，应用 EXE 与安装器的 PE 证书目录均为空，未签名；更新源保持为 `maaoding/llm-reader` 的 GitHub Releases。

本环境的构建区别：常规 `electron-builder --win nsis --publish never` 已完成应用打包，但生成卸载器时需要运行 32 位 NSIS 程序。云端内核拒绝 32 位 ELF（`Exec format error`），本地 Wine 与工具自带 Wine 均未能完成该步骤。最终使用 electron-builder 26.15.3 内置的 `UninstallerReader` 从中间 NSIS 文件提取卸载器，再由原来的 NSIS 流程完成安装器和 blockmap；没有修改应用或安装脚本，也没有运行最终安装器。这不是一次未经适配的 `pnpm build:win` 成功记录。

本地适配脚本为 `output/release-v0.7.0/build-nsis.cjs`，执行命令为 `node output/release-v0.7.0/build-nsis.cjs`，输入是上述 `release/win-unpacked` 目录；构建日志为 `output/release-v0.7.0/build-win.log`。此脚本只替换本次构建中生成卸载器的执行步骤，调用的是构建工具已有的提取器，保留其 PE/NSIS 签名、长度与唯一数据块校验。本次未在 Windows 上验证最终安装、升级与卸载行为。
