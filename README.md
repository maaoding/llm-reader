## v0.5.0

这一版把书库、阅读、章节笔记与对话组织成书籍工作台，并加入全书取材、可选 PDF 文档处理和会话恢复。查看[完整更新说明](docs/releases/v0.5.0.md)。

## 功能

### 书库与阅读

- 支持导入无 DRM 的 EPUB、UTF-8 TXT 或 PDF；本机已安装 Calibre 时，还可将无 DRM 的 MOBI/AZW3 转换为 EPUB 后导入。
- 支持文件多选与整窗拖拽批量导入（最多 300 个）：逐本顺序处理、单项失败不中断批次，可随时取消，完成后显示汇总；单文件上限为 250 MB，其中 TXT 为 64 MB。
- 导入文件复制到应用数据目录并按 SHA-256 去重，重复导入会直接打开已有书籍。
- 书库使用紧凑卡片，宽窗口每行三本，支持书名／作者搜索、最近打开排序和继续阅读入口；可查看格式、大小、语言、出版社、出版日期、简介等书籍详情。
- 打开书籍进入概览，可继续阅读、开始提问、查看准备状态、已有全书概述和最近保存的五条回答。多本书通过顶部标签切换，并记住各自停留的概览、阅读或章节笔记页面。
- 阅读进度放在标题栏，左侧窄图标栏提供目录、摘录、搜索、排版／显示和详情，右侧停靠阅读助手。
- 连续滚动阅读并恢复上次自然阅读位置；目录、搜索、摘录、笔记来源与回答引用的跳转不会覆盖该位置，偏离后可用“返回阅读处”继续。PDF 以连续页方式阅读，支持适合宽度、缩放、页码进度与有文本层页面的单页框选文字。
- 支持在本书内全文搜索，命中可逐个跳转且不破坏自然阅读位置。
- 标题栏显示当前章节与本章阅读进度；阅读区提供随界面明暗切换的默认、护眼纸张主题。
- 阅读设置可调整正文字号（80%–140%）、系统字体、行间距、首行缩进、正文宽度、段落间距与对齐。
- 删除书籍会同时清理该书文件、封面、摘录、笔记、会话与回答归档，且无法恢复。

### 划词与助手

- 选中原文后可“解释这段”“联系上下文”“自由提问”或“摘录这段”；前三种操作可自定义名称和图标，前两种还可自定义固定提示词。摘录在原文持久高亮，可从“摘录”面板跳回。
- 默认“解释这段”先讲清核心意思，再按需解释概念、句意和论证条件；“联系上下文”说明选区与已提供原文的具体关系，并给出依据。两者都要求区分原文与推断、说明信息缺口，避免固定模板和重复总结。升级会更新未修改的旧默认提示词，保留自定义内容；“自由提问”使用读者输入的问题。
- 提问范围分为“选中内容”和“整本书”：新会话默认整本书，划词操作切换至选中内容。尚未配置模型或准备原文时也能先写草稿。
- 原文未准备时，应用把选区与最多 6,000 个 Unicode 字符的当前章节上下文发送给用户配置的 OpenAI 兼容或 Anthropic Messages 接口。
- 原文就绪后，助手可在本书内检索原文，并结合已有章节笔记与近期对话回答问题。每轮的“本次参考原文 · N 处”可展开核对来源；有效引用能跳回原文，未知引用标记为未验证。
- 侧边助手与完整对话页面共用会话和草稿。支持流式回答、停止、追问、编辑最后一轮问题、重新生成、会话内搜索和标签排序。
- 跨书请求最多两个同时进行，更多请求进入队列；切换书籍不打断回答，清空会话会取消该会话的生成与排队请求。
- 每本书保留最近 20 个对话，每个保存草稿与最近 20 轮已结束问答。切换选区或提问范围前自动保存，可从侧边助手或完整对话的“最近对话”恢复；清空仅删除当前对话。重启恢复最近打开的会话标签及各自页面，生成中的回答不跨重启续传。长期保留的内容可主动“保存回答”。
- 顶部“回答归档”提供跨书搜索和继续追问，支持将全部、本书或单条归档导出为 Markdown，包含引用原文。

### 本书准备与章节笔记

从书籍工作台打开“本书准备”，三项任务分别展示状态、进度和操作：

| 项目 | 用途 | 是否必需 |
| --- | --- | --- |
| 原文准备 | 整理可检索的原文；EPUB/TXT 在本机完成，无需分析模型 | 整本书提问需要 |
| 章节笔记 | 使用所选模型整理概述、观点、条件、例外和概念 | 可选 |
| 按含义查找 | 使用 Embedding 服务帮助找到表达相近的原文 | 可选 |

- **原文就绪即可整本书提问**。笔记或按含义查找未开始、部分完成、暂停或失败，都不会阻断已就绪的原文问答。
- 各项支持独立的暂停、继续与重新准备／生成／建立；重启后不自动继续外部服务调用。重新准备原文会使章节笔记与向量需要重建，单独重建笔记或向量只影响对应结果。
- “章节笔记”按真实章节只读浏览，已完成部分随时可读。全书概述、章节汇总与笔记概述支持 Markdown；来源显示摘句和有效页码，失效来源明确提示。
- “设置 → 阅读增强”按服务分别配置。可选的“按含义查找”在本书内融合全文与语义检索；可选的“原文排序”通过 Rerank 服务调整候选原文顺序，两者失败均回退到可用的本地检索结果。
- PDF 原文准备可接入 **MinerU 本地服务／MinerU 云服务／Docling Serve**，支持 OCR 与语言选择。由用户主动开始并将整份 PDF 发送给所选文档服务；支持保留服务返回的章节、表格、脚注、公式及多页来源，并通过“文档检查”查看处理提示。
- **逐页 OCR**：可选择支持图片输入的 OpenAI 兼容模型或 Anthropic / Claude，也可选择 Mistral OCR、Unstructured Partition。到“设置 → 阅读增强”填写接口、模型与认证信息，测试图片识别并保存，再从“本书准备”开始。逐页显示进度，完成页本地缓存，支持暂停后继续；详见[服务配置说明](docs/provider-configuration.md)与[视觉模型 OCR 说明](docs/vision-ocr.md)。
- 扫描 PDF 可直接浏览，配置文档服务后可识别原文用于提问。准备完成后，Ctrl+F 可搜索本地缓存的识别文本并跳到对应页，搜索不会重新调用 OCR 服务。处理文字不替换 PDF 页面，也不会增加扫描页划词或跨页选区。PDF 导入上限为 250 MB，文档处理上限为 200 MB、600 页。

服务配置、请求范围与恢复行为详见[阅读增强说明](docs/knowledge-processing.md)。

### 设置与安全

- 设置分为“外观、阅读、划词操作、模型服务、阅读增强、关于”。界面主题支持浅色、深色与跟随系统，界面缩放可选 90%、100%、110%、125%。
- 模型设置支持保存多套命名配置并随时切换，可从接口拉取模型列表辅助填写；可独立测试文本回复和流式回复，测试读取有效文本并校验流式结束，设置入口显示 API 连接状态。
- 支持 OpenAI 兼容与 Anthropic / Claude 原生协议；模型、Embedding、Rerank 和文档服务均可独立设置请求头、额外请求参数及超时。认证请求头加密保存，也支持只用自定义请求头认证的模型接口。
- 应用启动时静默检查更新，设置中也可手动检查；发现新版本会展示更新日志摘要，由用户选择下载并重启安装。更新经 GitHub Releases 分发，安装前校验更新包完整性。
- 书籍文件、阅读位置、摘录、笔记、草稿、会话与回答归档保存在本机，结构化数据使用 SQLite（`node:sqlite`），无需注册 LLM Reader 账号，不提供同步或遥测。
- 问答和笔记生成会把所需文本发送给用户配置的模型；可选 Embedding 服务接收原文分块及查询，Rerank 服务接收问题与候选原文，MinerU／Docling 文档服务接收整份 PDF，视觉模型、Mistral OCR 和 Unstructured 接收逐页图片。应用不内置或自动安装这些服务，服务可能产生费用。
- API Key 与自定义请求头由 Electron `safeStorage` 加密：问答模型密钥保存在独立密文文件，阅读增强密钥和自定义请求头以密文保存在 SQLite；明文不进入日志或数据库，设置页不读回已保存的凭据。
- Renderer 保持 `sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`；窗口创建、导航、权限请求和外部网络请求均被拒绝，EPUB 内容按不可信输入处理。

## 安装

- 在 [GitHub Releases](https://github.com/maaoding/llm-reader/releases/latest) 下载 Windows x64 安装程序（名称以 `setup.exe` 结尾）。
- 安装程序支持选择安装目录，并创建桌面与开始菜单快捷方式；当前安装包未签名，Windows 可能显示安全提示。
- 如需导入 MOBI/AZW3，请先在系统中安装 [Calibre](https://calibre-ebook.com/)。

## 开始使用

1. 从书库导入书籍，进入概览后选择“继续阅读”。普通阅读无需模型服务。
2. 在顶部“设置 → 模型服务”中选择协议，填写 Base URL、API Key 和 model，测试连接并保存、启用。
3. 在原文中选中内容，点击“解释这段”，或在“本书准备”完成原文准备后直接围绕整本书提问。
4. 按需生成章节笔记、配置阅读增强服务；有价值的回答点击“保存回答”，在“回答归档”中继续使用。

模型接口需兼容 OpenAI `/v1/chat/completions` 或 Anthropic `/v1/messages`。远程接口必须使用 HTTPS，仅 `localhost`、`127.0.0.1` 与 `::1` 允许 HTTP。地址、自定义请求头及各文档处理商的配置见[服务配置说明](docs/provider-configuration.md)。

## 开发

```powershell
pnpm install
pnpm dev
```

开发环境需要 Node.js 24+ 与 pnpm 11+。

重装依赖后若 `pnpm dev` 报 `Error: Electron uninstall`，是 Electron 二进制的 postinstall 下载未执行，手动运行 `node node_modules\electron\install.js` 即可。

“请求适配”默认为“自动”，会识别 OpenCode Go 官方地址（如 `https://opencode.ai/zen/go/v1`）。通过中转调用 Go 时，选择“OpenCode Go”；测试连接和获取模型列表会直接使用当前表单选项。中转需透传会话标识；Go 请求遇到重定向时，请填写最终接口地址。此选项仅适配请求头，仍需选择支持 `/v1/chat/completions` 的模型。

应用以 `LLM-Reader/<实际版本>` 标识客户端；Go 请求使用随机 UUID 作为 `x-opencode-session`。追问、规划和重试复用对话 ID，归档重开保留该 ID；章节笔记生成单独维护 ID，暂停和继续保持不变，重新生成时更换。旧配置、归档和已有缓存自动迁移，升级不会自动重新准备书籍。详见 [Go 兼容验证记录](docs/go-compatibility-validation.md)。

## 验证

```powershell
pnpm lint
pnpm typecheck
pnpm test
pnpm test:e2e
pnpm test:all
pnpm build:win
```

`pnpm test:e2e` 会先执行文案校验和应用构建，再运行 Playwright；`pnpm test:all` 依次执行 lint、typecheck、完整单元测试、应用构建与 Playwright，避免重复运行文案测试。`pnpm build:win` 会在 `release/` 生成未签名的 Windows x64 NSIS 安装包，以及自动更新所需的 `latest.yml` 元数据；更新源在 `electron-builder.yml` 的 `publish` 中配置为 GitHub Releases。

验收已安装版本时，将 `LLM_READER_E2E_EXECUTABLE` 指向安装目录中的 `LLM Reader.exe`，再运行 `pnpm test:e2e:run`。测试仍会为每个用例创建并清理隔离的临时用户数据目录，不会读写日常书库。

需要使用日常设置中已保存的真实兼容 API 做发布前冒烟时，运行 `pnpm test:real-api`。该命令不会加入 `test:all`，只在主动运行时发送少量合成测试内容；它会把 Base URL、model、`safeStorage` 加密后的密钥文件及其本机加密上下文复制到临时用户数据目录，不输出或修改密钥，也不复制日常书库，并在结束后清理测试数据。

全书理解质量对照先运行 `pnpm build:app`，再运行 `pnpm eval:book-context` 检查样本与模型配置；此时不会调用模型。显式执行 `pnpm eval:book-context --run` 后，会发送约 9,000 字的合成书籍，并用同一配置比较六道固定问题在旧局部上下文与全书增强模式下的回答。默认使用当前配置，可通过 `LLM_READER_REAL_API_PROFILE_ID` 指定另一已有配置。报告写入 `tmp/book-context-eval-*/`，逐轮保留实际来源、回答、引用与接口返回的用量；程序检查证据召回，回答含义仍需人工复核。详见 [全书上下文验证记录](docs/book-context-validation.md)。
